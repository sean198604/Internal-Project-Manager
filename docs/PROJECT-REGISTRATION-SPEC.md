# 项目登记与归档资料采集规范

> 适用对象：向项目管理中心补录项目的人工或自动化 Agent。  
> 原则：只登记可从项目代码、部署环境、项目文档或负责人确认中核验的事实；不猜测、不伪造资料、不上传登录页截图充数。

## 1. 回传要求

每个项目请提供一份结构化资料包：

```text
项目编号/名称
项目基础信息（必填字段见下文）
部署记录（每个实际环境一条）
文档清单（至少一份）
图片清单（至少两张，均为非登录页）
归档与维护信息
证据来源与待确认项
```

如无法确认某字段，请明确填 `待确认`，并说明缺口和应向谁确认；不得编造默认值。

## 2. 项目基础信息

| 字段 | 是否必填 | 填写要求 |
|---|---:|---|
| 项目名称 | 是 | 使用系统正式名称；如有端口或服务器信息可放在副标题，不要替代名称。 |
| 简称 / 系统名 | 建议 | 用于列表展示和资产检索。 |
| 项目描述 | 是 | 说明面向谁、解决什么问题、主要能力；避免只写“内部工具”。 |
| 项目目标 / 业务价值 | 是 | 写清可衡量的业务目的或改善点。 |
| 需求说明 | 是 | 不少于 50 个字符，包含范围、用户、主要流程或关键约束。 |
| 所属部门、项目类型 | 是 | 从既有部门和类型中选择；不确定时标为待确认。 |
| 负责人、创建人、当前维护人 | 是 | 使用系统中已有账号；维护人可与负责人相同。 |
| 优先级、状态 | 是 | 归档资产状态应为“已归档”；软件运行状态另行填写。 |
| 开始、完成、验收日期 | 建议 | 不确定时不要补造日期，记录待确认原因。 |
| 验收人、验收说明 | 归档必填 | 说明谁确认了什么成果。 |

## 3. 部署记录（每个实际部署环境一条）

同一项目在内网、阿里云、测试机等不同位置部署时，必须分别登记，不能把多个主机拼在一条记录中。

| 字段 | 是否必填 | 示例 / 规则 |
|---|---:|---|
| 环境 | 是 | 开发、测试、预发布、生产。 |
| 主机名称 | 是 | `业务管理部03`、`阿里云服务器`；不要只写“服务器”。 |
| IP 或可访问域名 | 至少一项 | IP 填真实源站；域名填 `photo.seans.cc.cd`。Cloudflare/CDN 地址不能当作源站 IP。 |
| 端口、协议 | 是 | `443 / https`、`7021 / http`。 |
| 服务名 / 容器名 | 建议 | Docker Compose 服务或容器名称。 |
| 部署路径、运行时、数据库 | 建议 | 已核验再填；例如 compose 路径、Node/Python 版本、PostgreSQL。 |
| 当前版本 | 是 | 标签、Git commit、镜像标签或 `latest`（仅在确实无法获得更精确版本时）。 |
| 运行状态、最后验证时间 | 是 | 运行中 / 维护中 / 已下线，以及最后一次实际验证日期。 |
| 备注 | 建议 | 外网入口、反向代理、迁移限制、凭据位置（不得写明文密码）。 |

## 4. 文档资料

至少上传一份可维护的资料，优先顺序如下：

1. README、需求说明或使用手册；
2. 部署说明（启动、停止、更新、回滚、日志位置）；
3. 验收说明或测试记录；
4. 其他维护人员接手所需说明。

文档标题应说明内容，例如“部署与运维说明 v1.2”，不要使用“文档”“新建文件”等无意义名称。文档类型应与实际内容对应。

## 5. 图片资料（归档硬性要求）

每个归档项目至少上传 **2 张不同的真实图片**，每张建议 PNG/JPG/WebP，单张不超过 50 MB。

### 合格图片组合

1. **功能总览图**：已登录后的首页、仪表盘、主工作台或核心列表；
2. **核心流程 / 结果图**：关键表单、生成结果、详情、报表、任务执行结果或管理页面。

### 禁止作为归档图片

- 登录页、注册页、忘记密码页、空白页；
- 浏览器错误页、404/500、仅有加载动画的页面；
- 同一画面重复上传或仅裁切尺寸不同的重复图；
- 含密码、Token、Cookie、客户隐私、个人身份证件或不应公开业务数据的图片；
- AI 生成的概念图、与实际运行系统无关的宣传图。

### 图片标题格式

`功能名称 - 页面/结果说明`。例如：

```text
智能装箱计算器 - 装箱方案计算结果
企业内刊 - 文章发布管理页
场景图生成器 - 批量生成任务结果
```

回传时须说明每张图展示的功能、采集入口和是否已脱敏。

## 6. 归档与维护信息

| 字段 | 是否必填 | 填写要求 |
|---|---:|---|
| 当前软件版本 | 是 | 与部署记录保持一致。 |
| 软件状态 | 是 | 运行中、维护中、已弃用、已下线或未知。 |
| 特殊注意事项 | 是 | 风险、依赖、升级顺序、禁止操作、数据保留要求。 |
| 维护说明 | 是 | 启停、更新、回滚、日志、健康检查、故障入口。 |
| 交接信息 | 建议 | 代码仓库、部署目录、负责人与资料位置。 |
| 归档确认 | 是 | 明确由谁确认资料已可交接、可追溯。 |

## 7. 证据与质量检查

每项重要信息请附证据来源：代码仓库路径、Docker/Compose 输出、已部署网址、已有文档路径或负责人确认日期。不要上传密码、密钥、私有 Token 或数据库连接串。

提交前自检：

- [ ] 基础必填字段完整，需求说明不少于 50 个字符；
- [ ] 每个实际部署环境都独立登记；
- [ ] 至少一份可读文档；
- [ ] 至少两张非登录、非重复、可识别实际功能的图片；
- [ ] 图片标题和说明完整，敏感内容已脱敏；
- [ ] 版本、运行状态、维护与注意事项已核实；
- [ ] 所有待确认项和证据来源已列出。
